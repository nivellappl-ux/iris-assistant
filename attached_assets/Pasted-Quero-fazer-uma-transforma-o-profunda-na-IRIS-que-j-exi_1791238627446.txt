Quero fazer uma transformação profunda na IRIS que já existe neste projeto.

ATENÇÃO:

NÃO quero reconstruir a IRIS.

NÃO quero substituir a personagem.

NÃO quero alterar o Dynamic Island / Floating Island que já existe.

NÃO quero mudar o visual atual da personagem.

NÃO quero criar outra interface.

O Dynamic Island e a personagem IRIS devem permanecer exatamente como estão visualmente e estruturalmente, salvo pequenas alterações técnicas estritamente necessárias para conectar as novas funcionalidades.

O que quero mudar é praticamente TUDO relacionado à finalidade, inteligência, comportamento, arquitetura interna e forma como a IRIS funciona.

A IRIS foi inicialmente criada com uma finalidade diferente da que quero agora.

A partir deste momento, a IRIS deve ser concebida como:

“A inteligência operacional do Duvion.”

O Duvion é o sistema de gestão da empresa.

A IRIS é a camada inteligente que permite ao empresário conversar com o próprio negócio, compreender o que está acontecendo e executar ações dentro do Duvion.

Ela NÃO deve ser apenas um chatbot.

Ela NÃO deve ser apenas uma personagem que responde perguntas.

Ela NÃO deve ser apenas um assistente de computador.

Ela deve compreender o contexto da empresa e utilizar os dados e funcionalidades do Duvion para conversar, analisar, explicar, sugerir e executar.

⸻

1. NOVA FINALIDADE DA IRIS

⸻

A IRIS deve funcionar como uma assistente empresarial inteligente.

O utilizador deve poder falar naturalmente com ela através de texto ou voz.

Exemplos:

“Olá IRIS”

“Como está a empresa hoje?”

“Quanto vendemos este mês?”

“Porque é que as vendas caíram?”

“Quem são os nossos maiores clientes?”

“Quanto temos para receber?”

“Quais são as despesas que mais cresceram?”

“Existe alguma coisa preocupante na empresa?”

“Mostra-me os clientes que estão há mais de 30 dias sem comprar.”

“Cria uma tarefa para ligar para o João amanhã.”

“Regista esta despesa.”

“Mostra-me o fluxo de caixa.”

“Quais são as contas que vencem esta semana?”

“Resume a situação financeira da empresa.”

“Como posso melhorar as vendas este mês?”

A IRIS deve compreender a intenção e utilizar as funcionalidades do Duvion para responder.

⸻

2. DUVION + IRIS

⸻

A arquitetura conceptual deve ser:

DUVION

dados + módulos + operações + histórico + empresa

IRIS

inteligência + conversa + análise + interpretação + execução

A IRIS deve funcionar como uma camada sobre o Duvion.

Ela deve conseguir consultar informações autorizadas dos módulos existentes e devolver a informação de forma humana e compreensível.

Não quero que o utilizador tenha de navegar sempre pelo sistema para descobrir o que está acontecendo.

Ele pode simplesmente perguntar à IRIS.

⸻

3. OPENAI API

⸻

A OpenAI API já foi adicionada ao projeto.

A API KEY já foi configurada.

PORÉM, neste momento a conta/API ainda não possui créditos suficientes para realizar chamadas reais.

Portanto:

NÃO fazer chamadas desnecessárias à OpenAI.

NÃO criar loops que consumam tokens.

NÃO fazer chamadas automáticas constantemente.

NÃO utilizar a API simplesmente para testar a interface.

NÃO assumir que existe crédito disponível.

Criar uma arquitetura preparada para produção onde o provedor de IA seja separado da aplicação.

Criar algo semelhante a:

AI Provider
↓
OpenAI Provider
↓
IRIS Intelligence Layer
↓
Duvion Tools
↓
Duvion Database

A OpenAI deve ser apenas o provider de inteligência.

Não quero a lógica da IRIS diretamente espalhada pelo código.

Criar uma camada própria para a IRIS.

Exemplo conceptual:

iris/
core/
intelligence/
conversation/
tools/
context/
voice/
permissions/
memory/
providers/

E dentro de providers:

OpenAIProvider

Criar também um modo:

MockAIProvider / LocalAIProvider

para que a aplicação possa funcionar e ser testada sem consumir créditos.

Quando não houver crédito/API disponível:

A IRIS deve continuar funcionando em modo de demonstração.

Exemplo:

“Estou em modo de demonstração neste momento. A conexão com o meu modelo de IA ainda não está disponível.”

Mas a aplicação deve continuar permitindo testar:

interface
fluxo de conversa
estados
tool calling
dados simulados
ações simuladas
voz
memória
contexto

Quando a OpenAI estiver com crédito disponível, deve ser possível ativá-la sem reconstruir a aplicação.

7. COMPANY HEALTH

⸻

Criar uma das funcionalidades mais importantes da IRIS:

SAÚDE DA EMPRESA.

A IRIS deve conseguir avaliar o estado geral da empresa.

Não quero simplesmente mostrar números.

Quero interpretação.

Exemplo:

“Neste momento a empresa está estável, mas encontrei três pontos que merecem atenção.

As vendas caíram 12% em relação ao período anterior.

Os valores a receber aumentaram.

E as despesas operacionais cresceram acima das receitas.

Se quiseres, posso mostrar-te onde está o principal problema.”

A IRIS deve explicar os números.

9. SUGESTÕES

⸻

A IRIS não deve apenas dizer:

“As vendas caíram.”

Ela deve poder dizer:

“As vendas caíram 14% neste período. A maior redução veio dos clientes do segmento X. Posso mostrar-te quais clientes deixaram de comprar.”

E depois permitir:

“Mostra.”

Ou:

“Contacta esses clientes.”

Nesse momento a IRIS pode preparar a ação.

⸻

10. EXECUÇÃO DE AÇÕES

⸻

A IRIS deve poder executar ações dentro do Duvion.

Exemplo:

“Cria uma tarefa para ligar ao Manuel amanhã às 9.”

IRIS:

“Claro. Posso criar essa tarefa para amanhã às 09:00.”

Depois da confirmação:

create_task()

Outro exemplo:

“Regista uma despesa de 50.000 Kz referente ao transporte.”

Como envolve alteração de dados, pedir confirmação antes de executar.

21. MODO SEM CRÉDITO OPENAI

⸻

Como a OpenAI API já está configurada, mas atualmente não existe crédito suficiente:

Criar um modo de desenvolvimento.

Configuração conceptual:

AI_PROVIDER=openai

ou

AI_PROVIDER=mock

Quando:

AI_PROVIDER=mock

a aplicação deve utilizar respostas simuladas e dados de teste.

Quando:

AI_PROVIDER=openai

deve utilizar a API real.

Nunca colocar a API Key diretamente no frontend.

Nunca expor a API Key no browser.

Utilizar variáveis de ambiente.

Exemplo:

OPENAI_API_KEY

Criar também tratamento para:

insufficient_quota
rate_limit
timeout
invalid_api_key
network_error

A IRIS deve continuar funcionando visualmente mesmo quando a API estiver indisponível.

30. RESULTADO FINAL

⸻

O resultado que quero é muito diferente da IRIS original.

Não quero:

“um chatbot com uma personagem.”

Quero:

“uma inteligência empresarial que vive dentro do Duvion.”

O utilizador deve sentir que pode simplesmente falar com a empresa.

Exemplo:

“IRIS, como estamos?”

E ela deve conseguir compreender o estado do negócio.

Depois:

“O que mais me preocupa?”

Ela deve identificar os principais problemas.

Depois:

“O que devo fazer?”

Ela deve sugerir ações.

Depois:

“Faz isso.”

Ela deve executar, quando tiver autorização.

Esse é o objetivo central.

A IRIS deve evoluir de uma simples assistente virtual para a interface inteligente do Duvion.

IMPORTANTE:

Não começar redesenhando a interface.

Não começar criando outra personagem.

Não começar criando outro Dynamic Island.

Começar analisando o código existente e transformar a arquitetura interna e a finalidade da IRIS.

Preservar a IRIS visualmente.

Transformar a inteligência, integração, contexto, voz, ferramentas e capacidade operacional.

Antes de implementar qualquer parte complexa, verificar como o projeto atual está estruturado e reutilizar o que já existe sempre que possível.
